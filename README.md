## 建议审核结论

本稿已经按用户明确要求确定以下约束：

- 四仓整合为两个仓库，以当前检出的提交为功能基线，不合并其他分支。
- 模型计算设备只支持 Ascend；删除其他厂商设备实现及 CPU 模型推理后端。
- 保留 CPU 上的调度、tokenizer、普通张量辅助运算、共享内存及 KV 卸载。
- 支持离线 Python 推理和在线推理服务；删除训练协作专用入口。
- 模型范围仅保留 DeepSeek 和 GLM 原生文本生成模型，含已有 MTP、DSA。
- 删除多模态模型（包括目标系列的视觉、OCR、语音模型）和基于 Qwen/Llama 的蒸馏模型；先提取目标文本模型所需公共组件，再删除非目标模型实现。
- 保留当前分支目标模型相关能力，明确包括 DSA、CPU KV 卸载、跨实例缓存和 Prefill/Decode 分离，并纳入回归验收；相关 GLM 索引共享、不等 KV 分组、checkpoint、RemoteFill 及恢复路径随其保留。
- 首批验收使用 Ascend 910B3、CANN 8.5.1、PyTorch 2.9.0、torch_npu 2.9.0。
- 构建与验证在内部局域网实施，可通过 proxy 访问互联网；本机不执行构建。内网构建环境的 torch 已为 2.9.0，直接复用，不安排重装或升级。
- 验证环境禁止接入外部大模型/AI 助手服务；由内网人员或内网 CI 执行脚本，经人工审核和脱敏后交接必要结果，不建立大模型直接操作验证环境的链路。
- 本轮仅提交设计文档；收到用户审核通过并要求启动的指令后，才开始执行。

以下内容是为形成可执行方案给出的建议，尚非用户确认的需求：
